# Process and reservations hygiene audit

I traced child launch, shutdown, reaping, reservations, and fstrim through their callers in the lock, output, bench, and clean code. The findings are from static inspection. I changed no files and ran no builds, tests, or `brokkr` commands.

Two internal rewrites fit what the code is trying to guarantee. Give process management one owner for namespace identity, launch policy, signalling, reaping, and supervision. Give reservations one owner for admission, descriptor transfer, path identity, and reclamation. The existing APIs allow a caller to take an action after dropping the proof that made it safe. Shared constants would fix several instances of drift, while owned handles and typed transactions would remove that class of error.

Textlint can enforce string and API ownership, distinguish Rust code from comments and strings, restrict rules to production code, and check that a rule still scans its intended files. Script checks can compare several sources or exercise a protocol. Dependency rules can enforce a crate boundary if the process or filesystem code moves into its own crate. Fixture lints can prove that a configured Clippy ban actually fires. The repository already uses these approaches for state paths, the rustc probe, the dellingr seam, and the self-contained bench store. ## Process identity and reaping

- **The PID namespace check is outside the signalling API that needs it.** `VerifiedProcess::open` reads the same `/proc/PID/stat` before and after `pidfd_open`. With procfs mounted for an ancestor PID namespace, the reads can verify a process in that namespace while the syscall interprets the number in the caller's namespace. Stray, orphan, and watchdog reaping reach `kill_verified` without the holder verification used by `kill --hard`. Their exemption sets also combine `std::process::id()` with IDs from the snapshot. Require a verified local PID view before constructing a signalable identity. A namespace test with an ancestor procfs mount can prove refusal. [Process verification](/home/folk/Programs/brokkr/src/process/reap.rs:28), [Namespace check](/home/folk/Programs/brokkr/src/process/mod.rs:41), [Stray kill](/home/folk/Programs/brokkr/src/stray.rs:360), [Orphan reap](/home/folk/Programs/brokkr/src/test_orphans.rs:392), [Watchdog sweep](/home/folk/Programs/brokkr/src/shutdown.rs:770)
- **The stray reaper refreshes identities without refreshing why it selected them.** Between `find` and `kill`, a stray can exit and its PID can be reused. The original stray signal uses the old identity, while descendant expansion starts from that PID in the fresh table. A rust-analyzer starter is also selected by its old PID and name, then signalled using the fresh row's identity without checking the old generation or the fresh name. The final pidfd check can therefore faithfully signal a process the selection never authorized. Derive the target plan from one generation-aware snapshot, revalidate the roots and starters, and test PID reuse between scans. [Stray selection](/home/folk/Programs/brokkr/src/stray.rs:63), [Descendant expansion and delivery](/home/folk/Programs/brokkr/src/stray.rs:360)
- **Process names authorize a host-wide policy.** A locked command can kill a same-user Cargo job in another repository, children of a selected job, and the editor's rust-analyzer. Selection uses broad, mutable, kernel-truncated `comm` prefixes. The formatter exemption mistakes option values for the subcommand and treats an unreadable cmdline as a non-formatter. Descendant expansion also ignores the formatter exemption when a formatter sits under a selected root. The documented development-host assumption is consequential on shared development accounts and hosts with other build schedulers. Make destructive cleanup depend on positive containment or an explicit operator-selected scope. Fixtures can cover name collisions, option values, and formatters below selected roots. No name heuristic can establish ownership. [Stray rules](/home/folk/Programs/brokkr/src/stray.rs:79), [Formatter parser](/home/folk/Programs/brokkr/src/stray.rs:219), [Documented policy](/home/folk/Programs/brokkr/docs/commands/check.hygiene.md:464)
- **Holder protection can disappear on an inspection error.** `current_ownership` collapses an unreadable lock status and no holder into the same value. A same-namespace holder whose identity fails verification loses the extra exemption. The foreign path uses the recorded namespace inode as ownership evidence and treats `NS_GET_PARENT` returning `EPERM` as evidence that a candidate is outside that namespace. Permission restrictions can also produce that result. Carry a typed `Unknown` and refuse automatic destructive action when ownership cannot be established. Test unreadable lock status, stale namespace records, and permission failures separately. [Holder lookup and namespace walk](/home/folk/Programs/brokkr/src/stray.rs:158)
- **Orphan cleanup can discard the only recovery record after an incomplete scan.** A failed process-table read becomes an empty table, so the final `alive` check can remove every claimed registration. An unreadable environment is also treated as unmarked, deliberately trading recovery for bounded retention. A sandbox with restricted procfs can therefore forget a carrier visible to a later invocation. The serve reaper already distinguishes total scan failure from an empty result and rereads a process's generation after sampling its environment. Use shared `Complete`, `Partial`, and `Unavailable` scan outcomes, with a retention policy for inconclusive registrations. Fault-inject both kinds of read failure. [Orphan table and final cleanup](/home/folk/Programs/brokkr/src/test_orphans.rs:279), [Serve carrier scan](/home/folk/Programs/brokkr/src/serve/carriers.rs:61)
- **Environment marker readers already disagree.** The generic `/proc/PID/environ` parser skips a first matching entry with invalid UTF-8 and can return a later duplicate. The orphan parser takes the first match and then decodes it. Serve compares the first match as bytes. Lock observation caps the read at 1 MiB and can accept a matching final fragment without a terminating NUL. The unbounded readers collapse absent and unreadable. A shared byte-oriented reader can preserve the first match, truncation, and I/O status. Each marker can then validate its own value. Use duplicate, empty, non-UTF-8, cut-entry, and generation-change fixtures. [Generic parser](/home/folk/Programs/brokkr/src/process/helpers.rs:74), [Orphan parser](/home/folk/Programs/brokkr/src/test_orphans.rs:269), [Serve parser](/home/folk/Programs/brokkr/src/serve/carriers.rs:37), [Lock observer](/home/folk/Programs/brokkr/src/lock/collector.rs:385)
- **Reapers repeat traversal, retry, and reporting policy.** Stray selection walks 256 ancestors, expansion stops at a separate 64-depth limit, shutdown has a 65,536-row bound, and the in-flight diagnostic has its own copy of that bound without a visited set. The watchdog and hard kill each do two immediate sweeps. Serve and orphan cleanup each use three passes and a one-second settle budget. The orphan settle loop checks bare PIDs every 5 ms and uses start ticks as a proxy for leaves-first order. Tied ticks need not order parent and child. Use one indexed process snapshot, explicit traversal and retry policies, and stable identities through settle. Fixtures can enforce cycle handling, depth limits, tied ticks, partial scans, and signal outcomes. Snapshot tests cannot prove containment against concurrent forks. - **`ProcStat` is shared, but its acquisition, clock conversion, and failure semantics are not.** Sidecar repeats the stat read and PID check. The bench host trace rereads the boot ID independently. In-flight diagnostics use whole-second uptime, lock status computes with fractions and uses a 100 Hz fallback in its collector, watchdog history falls back to zero age, and sidecar formatting has its own `_SC_CLK_TCK` read. `ProcStat` drops an entire row if `comm` makes it invalid UTF-8, maps invalid parent/group fields to absence, and maps missing or invalid RSS to zero. `ProcTable` hides per-entry failures. Fixture tests can run without the host's `/proc` or clock. - **The lock-wait diagnostic is another kernel parser with its own gaps.** It excludes negative owner PIDs such as the sentinel used for open-file-description locks, reports only the first blocked row per PID, and later reads cmdline and descriptors by bare PID. It also implements Linux device-number splitting independently of the `libc` helpers used by fstrim. Read evidence through a process handle, keep “owner unavailable” distinct from “no lock,” and use one device-number type. Test with proc fixtures and identity changes between reads. Manual `strays --kill` returns success even when no candidate could be signalled. The orphan summary also omits PIDs on the premise that everything signalled is dead. Use one typed reap report with selected, signalled, exited, skipped, and unresolved outcomes. Keep the summary bounded and retain relevant PIDs and reasons in detail. Test mixed outcomes and a scan failure. ## Spawn, shutdown, and supervision

- **Admission and descriptor handoff depend on thread and call order.** A lease arms a thread-local slot with a raw FD and a program spelling. Another admission can overwrite it. An intervening launch of the same program can consume it. Moving a launch or call to another thread can miss the handoff or leave a stale raw FD in the original slot after release. The spawn succeeds when no matching slot exists. Pass an owned, single-use lease directly into the command that must inherit it, and return a child handle that owns the release obligation. The type can make a reserved spawn without a reservation impossible. Test two pending launches of the same executable, a cross-thread handoff, and a spawn refusal. [Armed slot](/home/folk/Programs/brokkr/src/reservations/launch.rs:442), [Spawn transfer](/home/folk/Programs/brokkr/src/process/spawn.rs:470)
- **Child environment ownership is split between constructors, adapters, and startup.** `command` applies hold policy before spawn, normal spawn restamps cohort and capability, `render_env` adapts the policy for nextest, and full-env spawn keeps the supplied environment and transfers the reservation FD without stamping an orphan token. The frozen bench caller compensates with an explicit addition. The config parser, nextest, detached spawn, frozen detach, peer launch, and bootstrap each choose their own reserved or stripped keys. For example, frozen detach removes the harness directory key, while the detached spawn list omits it. Bootstrap spells the harness key independently of its constant. Lua already refuses caller `BROKKR_*` keys and refuses `HOTPATH_*` on marked calls. Those guards make some branches redundant, while other launch modes still accept caller or inherited values where a policy stamp is absent. Define one per-variable precedence and absence policy and render it for each engine. Test missing, empty, inherited, and explicitly supplied values on every launch mode. - **Ambient environment and executable lookup have multiple owners.** Preflight and measured external calls repeat `PATH` precedence, using a Unicode ambient lookup even though the actual exec inherits OS strings. An absent path refuses bench lookup, an empty segment searches the child cwd, and the standalone launch helper intentionally uses a glibc-style `/bin:/usr/bin` fallback for an unset path. `freeze_env` and `Exact::of` separately rebuild an inherited environment plus overrides and removals. Exact spawn's “absolute path” contract is also a comment on a `&str` argument. ## Reservations and filesystem ownership

- **The serial transaction is a convention, and its wait budget covers only one lock.** `Store::scan`, `create_tied`, and `Lease::release_with` do not require a `Serial` token. The process mutex is acquired before the 120-second flock loop and has no timeout. Both locks can remain held across scans, fsyncs, recursive removal, `git worktree remove`, release polling, and an arbitrary release observer. A blocked filesystem call or reentrant observer can stall unrelated reservations. Make the transaction a required capability. Reserve a mutation's operands in a short transaction, perform the blocking work as the holder of that reservation, then finalize. A fake blocked filesystem, clock, and observer can exercise the boundaries. [Serial lock](/home/folk/Programs/brokkr/src/reservations/mod.rs:113), [Store operations](/home/folk/Programs/brokkr/src/reservations/store.rs:244), [Release observer](/home/folk/Programs/brokkr/src/reservations/store.rs:832), [Worktree mutation](/home/folk/Programs/brokkr/src/worktree.rs:650)
- **The per-user address is shared by convention and resolved repeatedly.** `Store::user` reads home for the durability anchor and reads it again through `brokkr_state_dir` for the root. `serialize` resolves the store separately from callers that later use it. The existing home resolver accepts any nonempty `HOME`, including a relative path. A different home or mount namespace can produce a different lock inode for a shared output tree. A missing home refuses lease creation, while mutation and clean reclamation can proceed without a store. The latter assumes no other process could have opened the relevant store. Resolve and pin one state root and reservation realm for the invocation, and require explicit proof for operations allowed without it. Test missing and relative home plus shared outputs across distinct roots. Local flock and shared filesystem semantics remain host prerequisites. - **Path resolution can approve an identity different from the path an operation uses.** Guard and read hold independently fall back to `/` when `current_dir` fails. Relative operands can then be screened against a fabricated base. `Spelled::resolve` stops inspecting after the first missing component, even if a later `..` backs out of that component. The kernel may instead return `ENOENT`, or a later retry may reach a symlink the resolver never inspected. The comparison has no identity for hard links, bind mounts, or case-folding filesystems. `statx` mount-ID failure falls back to device equality, so two mounts of one device can pass placement and later refuse rename. Use a single resolver with explicit bases, pinned parent descriptors, and identity for existing operands. Validate absent names separately. Test symlink retargeting, missing components followed by `..`, hard links, and alternate mount layouts. Later iterations and preflight opens resolve names again, and the per-call veto checks the new spelling alongside the old one. Those checks can prevent a declared write and still allow a read of different bytes under the old digest. The documented guarantee applies to cooperating writers, while builds, literal child paths, and namespace changes can take another route. If `mkdir` fails because the name already exists, `forget` tries to clear the record. A failed rewrite followed by failed or interrupted reclamation can leave the old record authorizing deletion of that existing path on the next scan. Even when an inode is recorded, `remove_private` checks and removes via separate pathname operations. It assumes no other actor can move or replace an ancestor or leaf once the lease is free.
