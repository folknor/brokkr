# Hygiene audit of worktrees, Git, cleanup, deps, Criterion and serve

This was a read-only review of the current source and local docs. I made no file changes and ran no builds, tests or `brokkr` commands. The failure cases below are deductions from the code. I could establish which compatibility fields have in-tree readers, but external use of the NDJSON fields and the presence of old files on deployed hosts remain unverified.

## Worktrees and Git

- **Resolve the effective Cargo directories once.** The disk gate always probes `<build root>/target` plus a nonempty ambient `CARGO_TARGET_DIR`, relative to the build root when needed. Cleanup and worktree placement use Cargo metadata's resolved target. The host `target` setting supplies a third answer for `env`. These rules already disagree. A full fallback volume can refuse an invocation writing to a roomy override, while a full volume selected in Cargo config can escape the gate. Existing worktree links can also keep pointing at a previous target volume. Worktree build and Crit generally pin `CARGO_TARGET_DIR` alone, while other build paths pin `CARGO_BUILD_BUILD_DIR` as well. A separately configured build directory can therefore sit outside the claimed worktree isolation. Give the gate, build, discovery and cleanup the same resolved pair of output directories, with an explicit answer for unknown mounts. Test relative, empty, configured, symlinked and independently overridden directories. Checkout canonicalization falls back to the supplied path, so a transient canonicalization failure can create a second identity.
