I read the scoped source and docs and followed the relevant calls into config loading, Git, child supervision, cleanup, and storage. I also checked the local litehtml-rs, sluggrs, pbfhogg, and elivagar checkouts where they implement the other end of a contract. This is a static audit. ## What the existing gates can enforce

- **The Rust output gate catches spellings, with gaps at the level and language boundaries.** Clippy denies direct stdout and stderr printing, and textlint catches named prefixes and warning tags. `output` already owns rendering, teeing, and path presentation. Those checks do not catch an `ERROR` embedded in a project message, an unredacted URL, a missing run ID, or a JavaScript diagnostic. Keep the existing gates and give visual commands a typed event interface. Use a JavaScript AST check for its permitted protocol writers and transcript tests for level, stream, and redaction. [Cargo.toml](/home/folk/Programs/brokkr/Cargo.toml:134), [brokkr.toml](/home/folk/Programs/brokkr/brokkr.toml:177), [output contract](/home/folk/Programs/brokkr/reference/output.md)
- **The convention gates can check wiring as well as source text.** Gremlins already cover JS and Rust source. Textlint supports production-only and code/string scopes, `must_scan`, and `require_live_paths`. Script checks can verify generated contracts and offline helper behavior. Cargo dependency rules govern direct package edges, so enforcing a boundary within today's single crate needs a source check or a crate split. Fixture lints can prove that a designated method is refused, for example direct process, environment, or filesystem access from a pure scorer. They cannot establish crash consistency or semantic equivalence. Those need fault-injection and contract tests. ## Runs, approvals, and artifact ownership

- **A sluggrs approval can pair one run's metadata with another render's image.** The renderer writes a mutable `output.png`. Approval checks that the file exists and that the latest SQLite row has acceptable Git provenance. If a later render writes the file and stops before writing its row, approval uses the earlier row and the later bytes. The same gap admits a manually replaced image. A first-run `NO_BASELINE` row establishes file existence without decoding the image, so even invalid PNG bytes can reach approval. Enforce this with a validated immutable render artifact keyed by run and subject, and allow approval only from a row referencing that artifact. Fault-inject after render and before row persistence. [Renderer](/home/folk/Programs/brokkr/src/sluggrs/cmd.rs:237), [no-baseline path](/home/folk/Programs/brokkr/src/sluggrs/cmd.rs:298), [approval](/home/folk/Programs/brokkr/src/sluggrs/cmd.rs:534)
- **Sluggrs baseline publication has two commit points.** Approval updates SQLite before renaming `approved.png`. A kill or rename failure leaves a new record with old or missing bytes. Conversely, a PNG without a record still participates in scoring as the comparator, including when its bytes changed since the last run. `visual-status` only consults the DB, so deletion or replacement can leave a previously passing row looking current. Sluggrs also lacks a completion marker, so rows from a partial batch immediately qualify as latest and its report reads like an ordinary run. Make the store publish one authoritative approval pointer to an immutable image, give both subjects the same run lifecycle, and test each interruption point. Treat any tracked image export as an explicit projection of that approval. [Publication](/home/folk/Programs/brokkr/src/sluggrs/cmd.rs:556), [status](/home/folk/Programs/brokkr/src/sluggrs/cmd.rs:607), [layout and latest-row policy](/home/folk/Programs/brokkr/src/visual/db.rs:39)
- **Litehtml's commit marker detects interruption by its own writer, but cannot certify the bytes.** `inspect` checks existence, width, and a nonempty ID. `publish` can therefore retire a good reference for an invalid PNG or layout dump. A hand edit retaining the ID passes the freshness check. The three renames also assume staging and `fixtures/` are on one filesystem. With a separate mount, `EXDEV` can arrive after the old marker was removed. An unlocked dashboard can sample during publication and show transient `STALE`. Use a fully validated immutable generation and a single atomic pointer, with hashes or equivalent binding to the bytes. Test a malformed generation, split mount, concurrent reader, and failed publication. Existing tests exercise marker states, including with placeholder PNG bytes. Sluggrs checks neither the width nor the fonts that produced the output. The commit stamp is abbreviated to nine hex characters and collected separately from status and the build.
