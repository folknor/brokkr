# Check orchestration hygiene report

I reviewed `src/check_cmd/`, `src/check_cmd.rs`, and `src/build_purpose*`, with the requested exclusions. I followed calls into Cargo, the test runner, config, output, locking, and storage where they establish a finding. The evidence is static. I read code and docs, changed no files, and ran no builds, tests, or `brokkr` commands.

The structural change I would make is to give each check invocation an owned run context, resolve each admitted Cargo request into one launch specification, and hand execution and accounting the same typed observations. The launch specification should carry the selected executable, cwd, environment precedence, artifact roots, runner, and resource claims. A separate run owner should manage deadlines, cancellation, output, and persistence. For direct lanes, an immutable artifact bundle would remove the need to infer ownership from whichever executables currently occupy a shared Cargo directory.

## Storage, bounds, and writes

- **The journal’s two writers are only coordinated for complete individual writes.** The watchdog bypasses the normal mutex by appending through a second descriptor. `O_APPEND` provides an append position for each syscall. Rebinding the descriptor with `dup2` also clears the close-on-exec flag on reuse.
