# Bench hygiene audit

I inspected the script-bench code, its documented contracts, and the storage, launch, reservation, and host code it calls. This was a read-only source audit. I changed no files and ran no builds, tests, or `brokkr` commands. The behavioral findings below follow from the code paths, without runtime reproduction.

I would rewrite the bench orchestration around a single prepared invocation, an explicit child-launch capability, and separate types for a measured result, its evidence, and a query summary. Today the arm runner, rounds runner, contract host, store, and renderer each reconstruct parts of those decisions. The resulting drift already changes reported timings, permits writes on the dry-run path, and can discard a measurement after it finishes.

## Child launch, Lua, and measurement

- **`PATH` resolution has two copies and can disagree with the child environment.** Preflight and measured external calls each pick the first explicit `PATH`, then use `std::env::var("PATH").ok()`. Empty means search the child's cwd. Unset or non-UTF-8 means lookup fails. ## Host assumptions, files, and locking

- **The dry-run digest path writes.** `PinsOnly` calls the caching digest implementation for pinned inputs. A cache miss on settled data can create `.brokkr/hash_cache`, its lock, and a staging file even though CLI help says the command stores nothing. Dry run also proceeds without the input hold used for a real run. Give dry run a read-only digest capability. Any regenerable persistent digest cache should belong to brokkr's cache layer, under its per-user cache root and keyed by project and filesystem identity. A filesystem write-denial test can enforce the dry-run contract. [Dry-run docs](/home/folk/Programs/brokkr/docs/commands/bench.md:388) · [Bench digest](/home/folk/Programs/brokkr/src/bench/params.rs:1185) · [Cache save](/home/folk/Programs/brokkr/src/preflight/digest.rs:784)
- **Digest validity assumes trustworthy filesystem stamps and cooperative writers.** The shared cache keys by canonical path and compares mtime, ctime, inode, and size, with a two-second settling window and no device number. Coarser or remotely supplied timestamps, mount changes, and external writers weaken those assumptions. Shape checks and digest opens are separate. A replacement between them can defeat the earlier type check, and tree digests record internal symlink target text rather than the contents reached through an external link.
