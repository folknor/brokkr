# Convention-gate hygiene audit

I reviewed the gate implementations, their config and check entry points, the Cargo and Git adapters they rely on, and the relevant manuals. This was source inspection only. I made no file changes and ran no builds, tests, or `brokkr` commands. The examples below describe behavior derived from the code.

I would rewrite the convention layer around three inputs that the current stages reconstruct independently: a validated gate plan, an invocation-owned view of the tree and tools, and typed evidence that a gate actually ran. The same plan should drive `check`, named selections, and audit. Cargo artifact proof, file ownership, deadlines, and diagnostic rendering need explicit owners across those entry points.

## Enforcement already in place

The repo already enforces several of the ownership rules in this audit. Cargo denies direct stdout and stderr printing, and textlint covers handwritten operator prefixes, `.brokkr` paths, duplicate rustc probes, access to dellingr, dependencies of the bench store, reservation-gated mutations, and durable documentation references. Gremlins and the markdown shortcut share an extension table. Textlint shares its selector calculation with audit, dependency rules share their package selector resolver with audit, and `check` and `deps` share the publication-cycle implementation. Those are working examples of enforcement at the owner. ## Tree, selectors, headers, and gremlins

- **The file list, status, identity, and bytes come from different observations.** Planning reads Git status, `TreeSnapshot` lists files and reads status again, presence is uncached, and bytes are read lazily. Canonicalization runs again at each read or write. An editor, a background script, or a retargeted symlink can change what a later gate sees. Canonical path keys also leave hard-link aliases as separate cache entries. The cache holds its mutex over blocking reads and writes, and retains everything it reads. Give the invocation one inventory and an explicit content consistency contract. Test changes between enumeration, presence, open, and rewrite. Use bounded reads and keep blocking I/O outside the shared cache lock.
