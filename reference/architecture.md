# Architecture

The module map: what each source file owns and why.

Single crate, single binary. No workspace.

### Source layout

- `src/main.rs` - module declarations and imports; `main_parts/bootstrap.rs` owns startup and command context helpers; the normal `main_parts/dispatch.rs` module owns dispatch. Shared argument resolution lives in `command_args.rs`; passthrough/timing, formatting, PMTiles statistics, verification, generic hotpath and visual approval have normal modules (`passthrough_cmd.rs`, `fmt_cmd.rs`, `pmtiles_stats_cmd.rs`, `verify_cmd.rs`, `generic_hotpath_cmd.rs`, `visual_approve_cmd.rs`). `command_input.rs` consumes the parsed CLI into concrete execution inputs. `project.rs` mints distinct private `ProjectRoot` and `BuildRoot` types; `context.rs` requires those types for measurement, lock and worktree setup.
- `src/clean.rs` - `brokkr clean` policy and cleanup implementation, including scratch, artefact, library run directory (by hand only, never after an interrupt), archive and worktree pruning through the typed layouts below
- `src/clean/layout.rs` - the project `.brokkr` state root (and its self-ignoring `.gitignore`), named per-project paths, constructed scratch targets and reserved FIFO/target namespaces; clean delegates archive retention to Elivagar's store
- `src/env.rs` - `brokkr env` report collection, formatting and command orchestration over typed host facts
- `src/host/` - typed CPU, kernel/io_uring, memory and storage probes used by environment reporting and history, with reusable storage and io_uring results
- `src/lock_cmd.rs` - `brokkr lock` and `brokkr kill` presentation and orchestration over `lockfile` and `lock_service`
- `src/cli/` - CLI definition (clap derive): `schema.rs` (`Cli`, `Command`, `ModeArgs`, `PbfArgs`, `VerifyCommand`) and `validation.rs` (value parsers) are normal private modules re-exported through `cli.rs`. The normal `visibility.rs` module defines the exhaustive `CommandId`/`CommandSpec` catalogue: applicability, config need, lock policy, worktree selection, disk gate, default mode, run log and tool probes. Dispatch, help visibility, project prefixes and man topics consume this policy. `COMMANDS` lists every `CommandId` for registry checks.

### Project-scoped help

`brokkr --help` lists only the commands that apply to the detected project. A hidden subcommand still parses; dispatch checks its command specification and refuses an inapplicable project before entering its handler. Project prefixes and man topic visibility read the same specifications.

- `src/bench_cmd/` - `brokkr bench`, the criterion runner (any Rust repo, not project-gated): `mod.rs` (the measure/compare split, baseline naming, the `CRITERION_HOME` store under `.brokkr/bench/`), `discover.rs` (bench targets from cargo metadata; owning package derived, never supplied), `stamp.rs` (the build-environment record and the shared-fields-only difference rule that gates `--compare`). See `docs/commands/bench.md`.
- `src/cargo/` - shared typed Cargo metadata snapshots, memoized once per root/query/environment for the invocation, with the indexed dependency graph; also the shared parser and per-root cache for `rustc -vV` facts, run from the project's directory so rustup selects its toolchain.
- `src/cargo_env.rs` - `[cargo_env]` evaluation and the shared `Phase` identifiers attached to its first failure. Before every cargo brokkr launches that can run a build script, each entry's command runs (`sh -c`, in cargo's launch directory, under cargo's env less every configured name) and its trimmed one-line stdout is set on that cargo. Applied at the spawn constructors (the captured, sidecar and passthrough runners in `output/child.rs`, the process-group spawn in `test_runner/procgroup.rs`) when the caller names the cargo spawn profile - never by matching the program name. The first failure is printed once and recorded process-wide: every later cargo is refused, and `main` (`seal`) and `check` fail the run even where a tolerant path swallowed the error.
- `src/tree_policy.rs` - the edits brokkr holds on a code tree for the locked window: `TreePolicy` (from `disable_toolchain` and `strip_rustflags`) and `HeldTree`, the guard the lock (or `with_worktree`, on a `--commit` checkout) owns. Activation always runs cargo config recovery first, policy or not, so a crashed run's filtered file is undone even after its key is gone. `restore_active_hold` is the watchdog backstop's bounded restore of every registered directory
- `src/toolchain.rs` - `disable_toolchain`: moves `rust-toolchain.toml` / `rust-toolchain` to a `.brokkr-disabled` sidecar and back, adopting a sidecar a hard-killed run left behind
- `src/cargo_config_strip/` - the top-level `strip_rustflags` key. `matching.rs`: physical token-sequence deletion from every rustflags value of the one file cargo reads in `<tree>/.cargo` (`-C`/`-Z` pairs grouped into units, all matches found against the original, overlaps and unplaceable matches refused, values keep their type, an unmatched file is never rewritten). `transaction.rs`: the rename-only (`renameat2` no-replace) install and restore over three reserved names, a self-verifying marker line, one policy-independent recovery state table shared by activation, drop, worktree admission and the watchdog takeover, and the process-wide mutex the backstop takes for good
- `src/check_cmd/check_plan.rs` - `plan_check`, the one planner of a check run (profile and claim, tested sweeps and lint lanes, derived doctest carriers, skipped phases, serial-build answers, every phase's selection), consumed by `cmd_check` to run and by `cmd_check_audit` to explain. Planning announcements go through a `Narrator` at the point they are decided: live on a run, collected by the audit. Also the audit's own findings (unreferenced `[[check]]` entries, package selectors naming no workspace package, absent `allow_exact` paths).
- `src/check_cmd/phase.rs` - `check` orchestration: run setup around the plan, convention/build sequencing, preparation handoff, accounting, and sequential test resolutions.
- `src/check_cmd/phase_type.rs` - the check-specific facts layered onto `cargo_env::Phase`: labels, skip/prose/group facts, ceilings, cargo verbs, and lint ownership.
- `src/check_cmd/reporter.rs` - the explicit `Check { commands }` / `Clippy` output policy used by the shared diagnostics pipeline.
- `src/check_cmd/diagnostics.rs` - clippy/rustdoc cargo runs, diagnostic attribution, merging, rendering, and failure excerpts.
- `src/check_cmd/clippy_cmd.rs` - the investigative `brokkr clippy` entry point over the shared diagnostic pipeline.
- `src/check_cmd/test_phase.rs` - the test-phase driver, lane execution, fail-fast accounting, and per-lane stop records.
- `src/build_purpose.rs` - the shared Cargo build-purpose resolver for run, install, check, clippy, test and bench; purpose policy owns profile defaults, feature admission and Cargo profile flags. Host `features` never reach it (measured builds merge them upstream; the standalone purposes do not inherit them). `src/build_purpose/requests.rs` owns package/feature request construction without check dependencies, and `src/build_purpose/features.rs` owns feature routing and projection; `src/build_purpose/environment.rs` owns sweep environment composition and isolated target-dir selection.
- `src/check_cmd/test_execution.rs` - sweep shape descriptions, support builds, serial harness attribution, the serial cargo-test runner, and the build verifier that holds that run's own artifact stream to the plan and settles its shim gate; `test_execution_tests.rs` holds the extracted check-command test coverage.
- `src/check_cmd/activation.rs` - check/clippy sweep activation, effective profile selection, and the shared ad-hoc environment merge. `brokkr clippy --sweep` resolves a `[[lint_sweep]]` name too; the ad-hoc env union stays `[[check]]`-only.
- `src/check_cmd/selection.rs` - check/test lane eligibility, package admission, dedupe, reach accounting and lane repro rendering; it hands the admitted package sets to the build-purpose request constructors. `RunSweeps` holds a check run's lanes - the tested sweeps, then the `[[lint_sweep]]` lanes - and `CheckSelections` builds clippy and rustdoc over all of them and the test phase over the tested prefix, which is all the test machinery is handed. Also derives a complete claim's doctest carriers (`derive_doctest_carriers`), keyed on the same effective build its dedupe uses, with the lint labels reserved.
- `src/check_cmd/conventions.rs` - convention-phase scans, finding blocks, and script-check failure rendering. Also `selector_findings`, the only place selector hygiene (dead globs, exclusions that excuse everything) is computed, read solely by `check --audit` (`cmd_check_audit` in `check_plan.rs`); the scanners themselves never warn about it.
- `src/check_cmd/member_check.rs` - the `member_check` phase: one package-mode `cargo check --locked` per workspace member over its production targets (lib, bins) in the `unify-package` target dir, the artifact accounting keyed by package id and target class, the by-name bin probe that waives only on cargo's own `required-features` refusal, and the candidate lost-features explanation.
- `src/check_cmd/fixture_lint/` - the `fixture_lint` phase: `mod.rs` runs each entry (preflight, lock transaction, per-variant `cargo clean -p` then warn-level `cargo clippy --no-deps --locked`, the non-fresh artifact requirement); `walk.rs` is the strict `syn` module walk (unconditional `mod` routes only - deliberately not `test_code`'s over-approximating classifier); `manifest.rs` the expectation manifest and exact lint-plus-backticked-path verdict; `lock.rs` external identity containment and path identity against the main resolve.
- `src/check_cmd/verdict.rs` - `Verdict`, stop precedence, the JSON summary schema, and test timings.
- `src/cargo_filter.rs` - the legacy cargo text reader for commands that still receive rendered diagnostics. Both it and the cargo JSON reader produce `diagnostic::Diagnostic`; `filter_clippy_with_owners` uses `OwnerIndex` for the same dependency-warning rule. Libtest output parsing lives in `src/test_runner/output.rs`; check's test-build and support-build warnings use cargo JSON plus stderr manifest-lint parsing
- `src/cargo_json.rs` - Parser for cargo's `--message-format=json` diagnostics (`parse_cargo_diagnostics`), feeding the shared diagnostic model. Also `manifest_lints_by_block`: cargo's own manifest lints (`cargo::unused_dependencies`, ...), which reach stderr only, as text - recognised by a `Cargo.toml` arrow plus a lint identity, then classified through `OwnerIndex` by check's clippy, test, and support-build paths. The old NDJSON `CheckEvent` output mode was removed (3ff8291); `check --json` now emits a single schema-versioned summary trailer built in `src/check_cmd/verdict.rs` (`CheckSummary`)
- `src/diagnostic.rs` - shared compiler and cargo diagnostic fields, rendering and dedupe identity, plus the metadata-backed `OwnerIndex` that classifies JSON diagnostics and stderr manifest lints. `Diagnostic::is_dependency_warning` is the shared warning-exemption rule. `check`'s clippy and rustdoc phases consume `Diagnostic` directly (merge on `DiagnosticKey`, render at error level). Lint namespace views use the borrowed `LintName` from `config::check`
- `src/rustc_text.rs` - the one reader of rustc-shaped text: `rustc_blocks` (column-zero `error`/`warning` headers open a block), the header rule, and `classify_block`/`classify_line`/`classify_diagnostic` sorting a block into finding, failure summary, cargo status (warning tallies, `build failed`) or progress. Shared by `script_check`'s failure excerpts, `cargo_json`'s summary filter and manifest-lint discovery, `cargo_filter`'s text parser and `check`'s failed-run reports, so they cannot disagree on what a diagnostic is
- `src/gremlins.rs` - Gremlin detector for `brokkr check`. Scans `.rs`/`.toml`/`.md`/`.markdown`/`.js`/`.sh`/`.py`/`.yml`/`.yaml` files case-insensitively, plus whatever `[gremlins].include` globs name (tracked + untracked-not-gitignored), for invisible/deceptive Unicode; the shared extension policy lives in `src/globs.rs`. `is_candidate` (extension or include, before exclusion) is shared with `check --audit`'s gremlins findings. Exposes `tracked_files()` (shared file walk) and `CodepointSet` (allow/ban singletons + ranges)
- `src/civil_date.rs` - shared proleptic-Gregorian `CivilDate` conversion between calendar dates and Unix time, used by `[header]` and HTTP-date parsing
- `src/header.rs` - `[header]` check: required file header with a current-year (`{year}`) requirement via the shared `CivilDate`. Ported from `check_copyright_year`
- `src/textlint.rs` - `[[textlint]]` engine: declarative forbid-a-regex-on-a-line rules with bounded predicates (`allow_marker`, `except`, `in_toml_section`, `table_row_only`). The generic engine for grep-style convention hooks. `test_code` (`skip` blanks test-only bytes, `only` blanks everything outside the test selection) works through `lex::mask_line_by` per rule, composing with `region`; the legacy `skip_test` key shares one preset-merge slot with `test_code` in the config parser and is rewritten to it on the merged rule; `must_scan` admission counts a file only at an eligible line holding real content (code in scope under `test_code`); an `only` rule refuses a file whose selection depends on an unresolved bare `#[test]`
- `src/test_code.rs` + `src/test_code/` - the test-code classifier behind `[[textlint]] test_code`, scoped to the unexpanded source model (the module doc states the contract). `cfg.rs` proves a `cfg` predicate false without `test` and, for the test selection only, with `test` (strong Kleene, `test` fixed, every other atom Unknown; the with-`test` proof also reads `cfg_attr`-introduced `cfg`s) and collects `cfg_attr` path alternatives; `facts.rs` is the `syn` visitor over one file under one inherited `Context` (test-only, dead in test builds) and resolution `Entry` (directory plus pending non-mod-rs stem), yielding module and literal-`include!` edges, masked spans, test-dead spans, bare-`#[test]` spans and their shadowing sites, refusals and tripwire evidence; `graph.rs` walks from `cargo metadata` target roots with per-context visit keys, intersects production masks across occurrences, keeps per occurrence what it proves test-dead to derive the test selection, classifies a second time with bare `#[test]` honored when a shadowing site leaves it unresolved (files whose selection differs are marked), and reads every source's contents through the caller's snapshot reader so masks describe the bytes the scan matches (module resolution, the ambiguity check and visit identity still consult the live filesystem). `textlint` runs it only when some rule with a `test_code` scope applies to a tracked `.rs` file
- `src/rustflags.rs` - Where a build's extra rustc flags actually come from, and how to add to them without discarding them. Cargo picks *one* rustflags source (encoded env > env > matching `target.*` > `build.rustflags`), so exporting `RUSTFLAGS` to add one `-A` silently drops the project's `-Dwarnings` and link flags. Inspects the whole config chain (build-root ancestors + `$CARGO_HOME`), including a small `cfg()` evaluator over a `Platform` (the host from brokkr's own `cfg!` values, or a `[[check]] target` sweep's triple from `target_platform`), and returns the live layer as a `Sink` - the target layer is live when the merged matching target flags come to something, string or array, as cargo decides it; injection at a config layer goes through `--config`, where cargo's array merge puts brokkr's entry last. Host triples come from `cargo::rustc`, so the selected project toolchain is used consistently. An unrecognised `cfg(...)` resolves to the inert direction, never the destructive one. Used by `check`'s test phase to carry `[lints] allow`. Also owns `EffectiveEnv` (a launch's env pairs over brokkr's own, empty values kept) and `CargoLaunchConfig` (one parse of the config chain for the host runner, a target sweep's runner, `build.target`, rustdoc, `build-dir` and `[env]`), read by the direct-execution lanes, the serial shim's fallback and the build-concurrency decision. `effective_rustflags` resolves the flags a host build gets and the source that won, by the same precedence, for build provenance
- `src/build_provenance.rs` - `BuildProvenance`: what a measured binary was built with beyond what its commit records, stored as a row's harness-owned `provenance.*` pairs. Host side (`host_pairs`, cached per build root and forgotten whenever a tree edit is applied or undone): the compiler's `-V` line, `effective_rustflags`, and the codegen keys and env inputs cargo reads; unit side (`unit_pairs`): the measured executable's resolved profile from cargo's compiler-artifact record. Rides `BuildIdentity`, which a suite building several binaries notes per build (`BenchHarness::note_build` / `forget_build`)
- `src/target_platform.rs` - a `[[check]] target` sweep's triple resolved against the toolchain cargo would use (`RUSTC`, `CARGO_BUILD_RUSTC`, `build.rustc`, `rustc`, under the sweep's env): the installed-target and cargo-version preflight, the triple's `rustc --print cfg` facts restricted to the names the triple alone decides, and its target libdir. Consumed by runner discovery, the rustflags sink, the direct runtime's per-binary libdir and nextest's build platforms
- `src/rustdoc_check.rs` - the rustdoc phase's lint-only mode: probes whether the rustdoc cargo will run supports `-Z unstable-options --check` (renders nothing; most of a `cargo doc` is rendering), places the flags without displacing the project's rustdocflags (appends to a set env source, else `--config build.rustdocflags`), and afterwards stamps each documented unit's `target/doc/<crate>/index.html` with the pre-launch time - cargo judges doc freshness by that file, which `--check` never writes, so without the stamp every run re-documents every member
- `src/check_cmd/binary_timings.rs` - `.brokkr/parallel-timings.toml`: one pure allocator assigns and orders binary slots from test counts and per-binary history. Serial cost (sum of its own tests) and the slowest single test are `Duration`s stored as integer milliseconds. Serial cost specifically, not wall time: wall time is a function of the slots granted, so feeding it back oscillates (measured as a two-cycle). The slowest test caps slots where extra threads stop helping. Advisory in every direction - a missing or stale file costs one warm-up run, never a wrong result
- `src/cpu_topology.rs` - physical cores in one last-level cache domain intersected with the calling thread's allowed CPUs, read from procfs (`Cpus_allowed_list`) and sysfs (`cache/index3/shared_cpu_list` collapsed onto `topology/core_id`). The default in-flight budget for a `parallel` `[[check]]` sweep, and `brokkr env`'s `l3 domain:` line. Not logical CPUs: SMT siblings contend for one core and cross-chiplet pairs pay fabric latency. On AMD the domain is a CCX/CCD, on Intel the die - one metric, two names, `domain_label` picks the word
- `src/test_runner.rs` - the stable crate-visible facade for the shared libtest runner. `context.rs` carries caller-supplied stop and warning behavior; `events.rs` owns stream observations; `outcome.rs` reduces those observations into one execution outcome and lane verdict; `plan.rs` owns strict-plan inputs, executable hashing and the `BuildGate` a cargo-launched run's connections wait on while the caller holds that run's own build to its plan; `deadline.rs` owns typed expiry, timeout cause and attribution, and the shared freeze/snapshot/kill verdict; `libtest_json.rs` parses and reconstructs libtest JSON; `procgroup.rs` owns process groups, pipes and drains; `run.rs` owns the one cargo/direct libtest runner and the separate listing runner; `hung.rs` owns timeout snapshots and reports; `output.rs` parses libtest text output and renders compact failures (separated from the cargo diagnostic text reader; check and `brokkr test` use it for post-run display and failure reporting); `harness_shim.rs` isolates each cargo-launched harness and rustdoc stream; `tests.rs` holds the runner unit tests. Moved crate-visible items are re-exported from `test_runner.rs`. Every libtest lane uses the JSON event stream (`-Z unstable-options --format json`, so nightly is required); the tracker reports typed `Expiry`, and `HungTest` carries exact, suspect or absent attribution separately from the timeout cause.
- `src/test_cmd/` - `brokkr test`: `plan.rs` handles sweep/package planning, build shapes and harness discovery; `run.rs` handles sweep execution and run accounting; `verdict.rs` classifies libtest outcomes and reports command verdicts; `display.rs` filters streamed output and repeat display; `focused.rs` validates and lists matching harnesses.
- `src/test_runner/harness_shim.rs` - harness isolation for `check`'s serial lane: brokkr installs itself as cargo's host target runner and as rustdoc, each harness says what it is in a handshake (role, and the executable cargo asked it to run - or, for rustdoc, the package directory, which a derived doctest carrier admits or declines per library), hands brokkr a fresh stdout pipe over a unix socket (authenticated by `SO_PEERCRED`, root-cargo parent, own executable) and execs itself, and brokkr drains each into its own tracker with a pidfd deciding liveness - so a harness that dies mid-test cannot leave the shared stream with an open suite that bills the next harness. One `Arc<SessionState>` carries the acceptor, watchdog, and drain state; typed refusal reasons fail closed on a strict session. Where the caller gave it a build gate, every connection waits for the gate's verdict before it is answered, and a strict session refuses anything but a clean build. Harness and cargo drains share `procgroup::join_drains` and its bounded grace. Also the entry point `main` checks first (`test_runner::maybe_run_harness_shim`)
- `src/test_scratch.rs` - the one scratch-dir allocator for unit tests (`scratch` for a directory, `scratch_path` for a file path). Asserts each `(module, name)` is used once: the allocator deletes before returning, so a shared name means two tests delete each other's files - invisible serially, an intermittent failure under concurrency. Exists because that precondition failed twice, both times a *shared helper* naming its own dir rather than a test picking a duplicate
- `src/globs.rs` - `globset` wrapper for the path-glob lists shared by `header`/`textlint`/`manifest`/`[gremlins].include` and the case-insensitive scanned-extension policy shared by gremlins and the prose-only shortcut
- `src/user_dirs.rs` - the one resolver for per-user directories: `home()` treats empty `$HOME` as unset; `brokkr_state_dir()` and typed accessors cover the global lock, compile lock, lock sockets, test-run registrations, nextest env, harness sockets, worktrees and the `[[install]]` ownership registry. Also `xdg_data_home`/`xdg_config_home` (an empty or relative XDG value counts as unset, per the spec), `cargo_home`, and `cargo_config_file(dir)` - the file cargo actually reads in a `.cargo`/`$CARGO_HOME` dir, which is the extensionless legacy `config` when both spellings exist. Shared by `guard`, `bench`'s stamp, `rustflags`, `history`, the sidecar backups and the user-wide config
- `src/user_dirs/paths.rs` - the shared per-user home, brokkr state-root and lock-path source included by `user_dirs.rs` and the standalone `rustc_guard` binary; explicit-home path helpers let the guard's decision use injected paths
- `src/lock_protocol.rs` - the shared lock and guard wire literals: environment names, lock path components, the published `auth` key, and the rustc-guard handshake; included by the standalone guard through `lock_probe.rs` and by the holder/path resolver
- `src/atomic_write.rs` - `replace(path, bytes)`: the one crash-safe file replacement (hidden sibling temp, fsync, rename, directory fsync; a symlinked target is resolved so the link survives, permissions carry over). Used for `brokkr.toml` dataset edits, the piners registries, `.brokkr/worktrees.toml`, `.brokkr/pbfhogg-capabilities`, the cargo config edited by `brokkr guard` and the `[[install]]` registry records (which add a strict directory fsync of their own)
- `src/scope.rs` - Scope helpers. `unstaged_files()` is the working tree against the index plus untracked files; `dirt()` classifies the working tree (`Unknown`/`Clean`/`ProseOnly`/`Code`) for `check`'s markdown-only shortcut using `git::TreeState` and the shared extension policy; `prioritize()` orders a phase's errors so the ones in files with unstaged changes come first; `TreeSnapshot` is one check run's file list, status and cached file bytes, shared by the convention scanners; the byte cache is keyed by canonical file identity, so every spelling of one file (including a symlink, `..`, or an absolute path outside the root that the test-code classifier reaches) reads the same bytes. Nothing is ever dropped - `check` has no output cap and no flag to raise one
- `src/measure/execution.rs` - one `MeasurementLoop` with a fixed `WallSource`, ordered `Iteration` evidence and winner selection; `BenchHarness::record` owns row-then-sidecar storage and failure fallback, and capture methods use the session lock and loop FIFO
- `src/measure.rs` - shared `MeasureMode` (Run/Bench/Hotpath/Alloc) and `MeasureRequest`
- `src/measure_dispatch.rs` - `dispatch_profiled`: the profiled-versus-measured mode split and profiler narration shared by the dellingr, mogwai and sluggrs adapters; each keeps its own build and harness calls
- `src/measure/runner.rs` - shared `CommandPlan` execution, `PlannedCommand`, `RowSubject` and binary/external/lifecycle plan kinds; owns mode selection, dry-run, recording policy and per-sample scratch lifecycle for pbfhogg, elivagar and nidhogg. `PlanTarget` (dry run, an opaque built `Executable`, or unbound) is chosen only here, so plans never read a second dry-run flag. A plan carries one planned argv value of its own `Argv` type, which dry run prints and the required `PlannedCommand::materialize` resolves into the `Invocation` that alone is spawned and recorded; non-binary plans refuse `materialize`
- `src/measure/argv.rs` - `Invocation` (a program borrowed from whatever resolved its argv, plus that argv and optional env; its path is readable only inside `crate::measure`, and callers spawn through it or the harness), the opaque `Executable` the runner hands plans (its path is readable only with the pbfhogg handle's `HandleKey`, and `Invocation::built` refuses a pbfhogg one), the closed `ExternalTool` set run from `PATH`, `ResolvedExecutable` for executables a named resolver produced, and `format_cli_args`. The invocation-taking harness runners record `cli_args` from the invocation they execute, and refuse one carrying an environment they cannot pass
- `src/{pbfhogg,elivagar,nidhogg}/plan.rs` - project input resolution, build shapes and execution hooks for the shared runner; nidhogg API/tiles provide HTTP/server lifecycle plans
- `src/elivagar/archive_store.rs` - `ArchiveStore`: the durable PMTiles store's canonical `<dataset>-<variant>-<commit>.pmtiles` names, `--commit`/`--file` resolution, admission and per-group retention (`prune`, shared by tilegen admission and `brokkr clean --archives`)
- `src/elivagar/artifacts.rs` - tilegen output promotion through `archive_store`
- `src/pbfhogg/commands.rs` - `PbfhoggCommand`, its valid inspect and tags-filter modes, command descriptors, and argument construction; `build_args` returns a `PbfArgv` built by the same match arm that decides its arguments
- `src/pbfhogg/argv.rs` - `PbfArgv`, a pbfhogg argv and what it reads, writes and scratches, built by the same calls, and the overwrite decision that follows from them
- `src/pbfhogg/binary.rs` - `PbfhoggBinary`, the handle on one built pbfhogg CLI executable that every pbfhogg CLI spawn goes through: it resolves a `PbfArgv` into a reserved `Invocation`, appending `--overwrite`, `--staging-dir` and `--tmp-dir` (the last two naming a per-launch private directory) where the argv needs them and the executable accepts them, decided per subcommand by a parser probe (bounded: a wall, its own process group, the run variables removed) and persisted in `.brokkr/pbfhogg-capabilities` keyed by the executable's XXH128; `run_in` is the run-scoped form, one supervised launch inside a library run directory (cwd there, the whole run directory as coverage, a wall, the run variables removed, the executable re-checked after the probes) whose outcome keeps an unsafe admission or release apart from a failed run (`measure::Supervised`). A handle holds the brokkr lock and is registered with `build::executable_guard`, which refuses any cargo spawn through the build seam while a handle lives, so a handle always runs the bytes it probed; it exposes no path, and the `pbfhogg-executables-through-the-handle` and `pbfhogg-executable-seams-not-imported` textlint rules keep the build seams out of the rest of `src/pbfhogg`. It also owns `LibraryHarness`, the same kind of handle on the built library harness (`[pbfhogg.library.harness]`, built through `harness_build`, together with the release CLI for a run, both builds before either handle): lock, build registration, re-stat before each spawn, no path exposed; it runs describe mode with the run variables removed from the environment and a sentinel byte past the size limit, and run mode as one reserved launch covering the whole run directory, its private directory inside it, the FIFO attached, output capped for the report, the deadline enforced and the launch released before it returns

Modules: `canonical` (the FROZEN streaming tile hash), `canon_sink` (shared canonical byte writer), `layout` (corpus paths and SVG names), `digest`, `diff`, `contract`, `manifest`, `render`, `style`, `mutate`, `fixture`, `sort` (bounded-memory multiset hashing). See `docs/projects/elivagar.md`.

- `src/elivagar/regress/` - the native two-archive semantic diff: `engine` (three-pass raw/canonical/detail), `prepared`, `compare`, `pairing`, `geometry` (exact-integer bbox/Hausdorff/KD-tree), `report`, `overlay`. Pass 2 calls `corpus::canonical`'s hash, so regress and the gate share one definition of "the same tile".

See `docs/projects/ratatoskr.md`.
- `src/dellingr/` - `brokkr dellingr`, the Lua-workload bench. `workload.rs` (the `[dellingr.workloads.*]` registry: `--lua NAME` -> the registered relative path, its parsed XXH128 file digest verified via `preflight::verify_file_digest` against the file under `project_root`, so a `--commit` run takes the harness from the worktree and the workload from the current tree), `cmd.rs` (resolve every selected workload - the `--lua` names, or `--all` - up front, build the `example` target once with mode-dependent features, then per workload - through `bench_variants::run_variants` when there are several - `run_external` for `--bench` or `capture_hotpath` for `--hotpath`/`--alloc`, handing the harness the registered path with the project root as cwd). Rows are filed under the workload name with `input_file` = `PATH@<full xxh128>`, so workload generations and the bench/hotpath files never pair in a comparison. See `docs/projects/dellingr.md`.
- `src/mogwai/` - `brokkr mogwai`. Two surface kinds, one row shape, no layers: argv-shaped surfaces go through the registered bin and need no registration (`brokkr mogwai -- gen ...`), harness-shaped ones resolve a name against `[mogwai.targets.*]` to a cargo example plus the features it must be built with (`targets.rs`). Features live in the registry because `--hotpath`/`--alloc` are inert without them - that is why the predecessor recorded profile-less rows; a call-site `-F` appends rather than replaces. `cmd.rs` branches on mode - `run_hotpath` + `capture_hotpath` for `--hotpath`/`--alloc` (the report is a file the child is told about, so `run_external` would record a row with no profile in it), `run_external` otherwise - filing rows under the target (or bin) name with the invocation captured verbatim in `cli_args`/`brokkr_args` - pairing is a query (`--grep` selects an arm, including one defined by an absent flag), not a name lookup. The `[mogwai.workloads.*]` registry, `meta.timing`, `meta.identity_counters` and `[<host>.corpus.*]` were removed wholesale (see the doc's removal table); out-of-git inputs are `[<host>.datasets.*]` with a plain `path`/`xxh128`. See `docs/projects/mogwai.md`.

See `docs/commands/corpus.md` and `docs/projects/piners.md`.
